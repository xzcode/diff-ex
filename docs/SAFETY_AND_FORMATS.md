# 文件行为、格式语义与恢复边界

更新日期：2026-11-27。适用于当前 M0–M3 首版基线。本文用于判断一次比较或写入究竟做了什么，也用于后续修改时保留现有行为。

## 1. 桌面与浏览器预览

| 能力 | 桌面应用 | 浏览器预览 |
| --- | --- | --- |
| 打开文件 | 原生对话框、原生拖入、读取磁盘路径 | 浏览器选择/拖入用户提供的文件 |
| 文本编辑与原文差异 | 支持 | 支持 |
| 规则比较算法 | Myers、Patience、Histogram | Myers；其他算法明确提示需要桌面版 |
| JSON 结构比较 | 支持 | 支持 |
| YAML、XML 结构比较 | 支持 | 明确提示需要桌面版 |
| 保存 | 检查磁盘指纹并写入目标文件 | 生成 UTF-8 下载，不直接修改原文件 |
| 目录比较、预览与同步 | 支持 | 不提供原生目录操作 |
| 工作区 | 应用数据目录中的 JSON 快照 | 当前浏览器来源的 localStorage |

比较与解析不向远程服务发送正文。应用工作区会保存打开的正文和未保存编辑，属于本机数据；它不是加密保险库。浏览器存储仍受浏览器配额和清理行为影响，失败会显示错误。

## 2. 编码、BOM 与换行

### 读取编码

原生读取支持 UTF-8、UTF-16LE、UTF-16BE、GBK、GB18030。

- 自动模式优先识别 UTF-8/UTF-16 BOM；没有 BOM 时严格按 UTF-8 读取。
- GBK、GB18030 和没有 BOM 的 UTF-16 需要明确选择读取编码；不会猜测一种编码然后静默接受乱码。
- 显式读取编码与检测到的 BOM 冲突时，返回错误。
- 非法字节序列不使用替换字符代替。UTF-8/GBK/GB18030 解码后出现 NUL 字符时拒绝作为普通文本编辑。
- 文件符号链接不能直接编辑，应明确打开其目标。目录、管道、套接字和设备文件不作为文本读取。

### 保存格式

输出编码、BOM 和换行是文件保存设置，与结构化比较规则相互独立。选择 GBK 或 GB18030 时不能写入 UTF BOM；无法用目标编码表示的字符会在写入前报错。UTF-16 按所选字节序编码，BOM 可选。

| 换行设置 | 保存行为 |
| --- | --- |
| LF | 将正文中的 CRLF、CR 统一为 LF |
| CRLF | 将正文中的 CRLF、CR、LF 统一为 CRLF |
| CR | 将正文中的 CRLF、LF 统一为 CR |
| `none` | 不转换传入正文；通常来自没有换行的文件 |
| `mixed` | 核心保留传入正文；桌面编辑流程要求用户先明确选择 LF/CRLF/CR 再保存 |

Monaco 会统一编辑模型的换行方式，所以不能承诺修改后的混合换行文件逐个保留原始分隔符。界面检测混合换行后明确提示选择输出格式。BOM 和统一换行格式不等于原始字节布局全部保持不变。

## 3. 文件保存与磁盘变化

文件打开时记录实际字节的 BLAKE3 指纹。保存现有文件必须提交该预期指纹：

1. 目标必须仍为普通文件，实际指纹必须匹配。
2. 编码和换行转换必须先成功。
3. 新内容写入目标父目录中的临时文件，刷新文件数据。
4. 发布前再次检查目标；已有目标采用原子替换，新目标使用不覆盖已有路径的发布方式。
5. 返回保存后正文、格式、字节数和新指纹。

原文件被外部修改、移动或删除后，普通保存会拒绝覆盖，用户需要重新打开或另存为。恢复旧会话不会放宽此检查。

另存为时，`inspect_save_target` 区分“目标不存在”“已有普通文件”“无法读取或不允许的文件类型”。它可以对二进制目标计算指纹，不需要先把目标解码成文本。覆盖已有文件须经过界面确认；确认后若目标又改变，保存仍会失败。

文本普通保存不自动创建历史备份。目录同步的备份机制是另一条流程，不能把它当作每次编辑保存的版本历史。原子替换保留基本权限，但不保证保留原文件的所有权、ACL、扩展属性或硬链接关联。

当前进程中的原生文件写入由锁串行执行。检查和替换之间仍存在外部进程竞争的系统调用窗口；本工具不提供对恶意本地文件系统修改者的隔离保证，也不保证断电时整个目录或工作区事务持久化。

## 4. 文本比较语义

原生文本算法支持 Myers、Patience、Histogram。规则支持：忽略大小写、忽略行首尾空白、忽略全部空白、忽略空行，以及忽略 CRLF/LF/CR 的分隔符差异。

规则只改变比较键，不修改原文。忽略换行风格默认不会把“存在最后一个换行”与“没有最后一个换行”合并；最后一个空行仍参与比较，除非启用忽略空行。

Monaco 显示和合并的是原文差异，规则统计来自独立比较引擎。开启规则后可能出现“按规则相同，但原文仍有高亮”。合并按钮不会自动删除忽略的空白或重写整份文档为规范形式。

首版没有基于语法解析的“忽略注释”、自定义正则忽略规则、移动代码块识别或三方冲突合并；不能将这些早期规划项理解为已有功能。

## 5. JSON、YAML、XML 结构比较

结构比较区分新增、删除、值变化和类型变化。路径使用 JSON Pointer：根路径为空字符串，键名中的 `~` 与 `/` 分别转义为 `~0` 与 `~1`。规范表示以 JSON 展示，属于只读检查结果；保存始终写原始编辑文档，不把该表示隐式写回 YAML/XML。

### JSON

- 忽略对象键的排列顺序，但键名始终区分大小写。
- 重复对象键报错，不能只保留最后一个值后宣称相同。
- 数字按精确十进制值比较，`1`、`1.0`、`1e0` 相同，数字 `1` 与字符串 `"1"` 不同。
- 大整数和小数不先转换为 JavaScript Number 或 Rust `f64`。巨大指数以系数和指数规范化，不展开成相应数量的零。
- 数组默认保留顺序。显式忽略数组顺序时按保留重复次数的集合比较，不能把 `[1,1]` 当作 `[1]`。
- 忽略大小写仅作用于字符串值，不折叠对象键。
- 不接受 JSON 注释或尾随逗号。

### YAML

YAML 先解析为有类型的数据，再转换为可比较表示；支持别名及合并键语义，并检查重复键。注释和排版不会作为结构差异。

当前语义范围要求映射键为字符串。不支持的非字符串键、自定义标签、非有限数值和解析错误会明确报错，可改用文本比较。不要把它当作任意 YAML 文档的通用转换器。

`serde_yaml_ng` 的数值路径可能经由浮点表示。额外的 `yaml-rust2` 事件校验会读取真实标量及位置，检查转换后的数学值和类型是否与原始标量一致。会发生精度丢失、溢出、下溢或类型变化时，结构比较拒绝该文档并提示位置，避免不同数值被舍入成“相同”。此策略没有实现任意精度 YAML 全面加载；普通可保持语义的数值正常处理，受影响文档仍可使用文本比较。

JSON 的数组顺序和字符串值大小写规则同样用于 YAML 数据。

### XML

- 使用命名空间 URI 和本地名称比较元素及属性；等价命名空间前缀变化不直接构成差异。
- 属性顺序不影响比较，子节点顺序始终保留，忽略数组顺序选项不用于 XML。
- 保留文本节点、注释、处理指令和它们的顺序；缩进空白也是文本，因此重新排版可能产生差异。
- 忽略大小写只作用于文本、注释、属性值等数据，元素名、属性名和处理指令目标仍区分大小写。
- 禁止 DTD，不使用外部实体解析器，不读取引用的本地文件或网络资源；标准字符引用可以解析。

这里的规范表示是应用内部节点表示，不是 W3C C14N、XML Schema 验证或业务语义等价证明。

## 6. 目录比较与忽略规则

内容模式流式计算 BLAKE3。元数据模式仅比较文件大小和修改时间，适合快速查看；相同元数据不能证明内容相同。同步预览总是重新进行内容比较。

扫描不跟随符号链接；链接可以作为条目比较目标路径。文件与目录类型不一致显示冲突，读取失败显示错误，不能把失败降级为“不存在”。目录自身状态汇总其纳入范围的后代差异。

支持隐藏项开关、自定义 gitignore 风格排除模式和各级 `.gitignore`。当前不读取全局 Git ignore 文件或根目录之外的父级规则，也不要求目录必须是 Git 仓库。无效忽略规则会报错。

**两侧 `.gitignore` 取并集用于最终结果。** 路径只要被任一侧规则忽略，就不会因另一侧可见而成为复制或镜像删除目标。例如，左侧忽略 `cache/` 时，右侧的 `cache/local.db` 不会作为“右侧多余文件”被删除。忽略策略校验会拒绝符号链接形式的 `.gitignore`。`.diff-ex-backups` 目录始终排除。

非 Unicode 路径无法安全通过当前字符串契约表示，会明确报错。首版没有重命名识别；重命名表现为一侧缺失和另一侧新增。

## 7. 同步模式、备份与取消

| 模式 | 内容来源 | 多余路径处理 | 两侧同名内容不同时 |
| --- | --- | --- | --- |
| 左 → 右更新 | 左侧 | 保留右侧独有项 | 备份右侧后复制左侧 |
| 右 → 左更新 | 右侧 | 保留左侧独有项 | 备份左侧后复制右侧 |
| 左 → 右镜像 | 左侧 | 删除纳入范围的右侧独有项 | 备份右侧后复制左侧 |
| 右 → 左镜像 | 右侧 | 删除纳入范围的左侧独有项 | 备份左侧后复制右侧 |
| 双向 | 各自独有项复制到对侧 | 不自动传播删除 | 显示冲突并跳过 |

双向模式没有共同历史基线，不能判断哪一侧更新，也不能把删除和从未存在可靠地区分。不会根据修改时间选择赢家。类型冲突和需要修改的符号链接同样跳过，不自动递归替换文件/目录。

两个同步根目录必须独立，不得相同或互相包含。执行前核对整个纳入范围的快照，再在每项操作前检查相关源、目标及父目录；如果预览已经过期，要求重新比较和预览。

覆盖或删除前，旧内容保存到被修改根目录中的：

```text
.diff-ex-backups/<plan-id>/left/<relative-path>
.diff-ex-backups/<plan-id>/right/<relative-path>
```

`left` 或 `right` 标识被修改的一侧。执行结果提供该计划的备份根路径。备份保留原内容和基本文件信息，不自动清理；这是同一磁盘上的恢复副本，不是独立的灾难备份。当前没有一键回滚界面，可从结果给出的位置手动恢复。

复制和哈希循环支持取消。取消或错误会停止后续操作，尚未发布的临时文件不会成为目标文件；已发布的文件和已完成的删除保留。结果中的完成数、跳过数和问题列表必须一起查看：跳过可能表示冲突、被保留的非空目录、取消后未执行项或错误后的剩余项。

目录删除只删除空目录。被忽略内容或执行期间新出现的内容不会被递归清空。同步不保留所有权、ACL、扩展属性和硬链接关系，不保证整个目录的事务原子性或自动回滚。

## 8. 工作区保存与恢复

桌面路径由 `app.path().app_data_dir()` 决定。目录内主要文件：

| 文件 | 用途 |
| --- | --- |
| `workspace.json` | 当前会话、正文、保存基线、比较规则和偏好 |
| `workspace.previous.json` | 上次正常写入前的快照，随正常自动保存轮换 |
| `recovery-<timestamp>-workspace.json` | 用户执行恢复/重置前归档的当前原文件 |
| `recovery-<timestamp>-workspace.previous.json` | 同次恢复/重置归档的上次快照（如存在） |

正常写入使用临时文件、文件数据刷新和原子替换；前端队列及原生锁避免当前进程并发覆盖。恢复同时检查 JSON、工作区版本、会话和偏好格式。

恢复失败后暂停自动保存并保留原文件。用户可以尝试上次快照，或选择“备份后重置”；恢复/重置先复制原文件到带时间戳的归档，归档失败则不继续覆盖原工作区。关闭尚未解决恢复问题的窗口也不会自动保存一个空工作区替换原文件。

应用加载恢复期间阻止创建会话；文件写入或同步尚未结束时阻止关闭。正常关闭先处理未保存编辑提示，再持久化最后状态。未保存编辑存入工作区不等于原文件已经保存。输出编码、BOM、换行的修改也属于未保存修改。

浏览器预览使用 `diff-ex.workspace.v1`。重置前把原值复制到 `diff-ex.workspace.recovery.<timestamp>`，不提供桌面版的上次快照恢复能力。工作区恢复不恢复 Monaco 撤销栈。

## 9. 容量与当前边界

首版不设置文件数量、标签数量或文件大小的业务配额。实际容量受内存、磁盘、浏览器存储和底层解析器能力约束。

目录文件哈希和同步复制按块读取，但目录列表、计划快照、文本原文、Monaco 模型、结构树、规范结果以及工作区 JSON 均可能常驻内存。虚拟滚动不等于数据本身分页。特别大的文本和结构文件尚未采用分页或内存映射；不应据此宣称任意大小文件都能精确编辑。

首版尚未实现图片/二进制/表格/压缩包/远程/Git/数据库/Office 文档比较、三方合并、CLI、任务暂停和完整跨进程工作区协调。当前进程锁不是跨应用实例锁；避免同时运行多个实例编辑同一工作区数据目录。
