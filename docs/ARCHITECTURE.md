# Diff EX 架构与开发边界

更新日期：2026-11-27。本文描述仓库当前的 **M0–M3 首版基线**，以实现代码为准。它不表示早期规划中的二进制、图片、表格、三方合并、远程文件、Git、压缩包和文档对比已经实现。

## 1. 运行形态

Diff EX 是本地桌面应用：Vue 3 + TypeScript 构成界面，Monaco 提供文本编辑和原文差异视图，Tauri 2 将界面连接到独立 Rust 核心。处理用户文件不需要服务端、账号或上传。

同一套前端也能由 Vite 启动为浏览器预览。预览用于体验界面、文本编辑及 JSON 比较；它不具备桌面版目录扫描和同步能力，也不模拟成功结果。桌面与预览的实际差异见 [格式与文件行为](SAFETY_AND_FORMATS.md)。

## 2. 目录和职责

| 位置 | 当前职责 |
| --- | --- |
| [`src/App.vue`](../src/App.vue) | 会话标签、主题和语言、文件打开与保存、窗口关闭、工作区恢复及异步写入期间的交互控制 |
| [`src/contracts.ts`](../src/contracts.ts) | TypeScript 会话、文件、对比结果、目录条目和同步预览契约 |
| [`src/components/TextCompare.vue`](../src/components/TextCompare.vue) | 可编辑双栏/单栏原文差异、逐块合并、定位、查找、折叠相同行和文本规则 |
| [`src/components/StructuredCompare.vue`](../src/components/StructuredCompare.vue) | JSON/YAML/XML 原文编辑、只读规范表示、可搜索的结构变化列表 |
| [`src/components/FolderCompare.vue`](../src/components/FolderCompare.vue) | 目录路径、递归比较结果、过滤和排序、虚拟滚动、同步预览、取消及执行结果 |
| [`src/lib/bridge.ts`](../src/lib/bridge.ts) | Tauri IPC 与浏览器预览分流、原生文件对话框、文件下载、同步任务活动状态 |
| [`src/lib/workspace.ts`](../src/lib/workspace.ts) | 工作区数据版本、会话默认值、格式校验、正文和保存元数据的脏状态 |
| [`src/lib/preview.ts`](../src/lib/preview.ts) | 浏览器文本与 JSON 比较实现；不作为原生文件写入依据 |
| [`src/lib/compare-ui-merge.ts`](../src/lib/compare-ui-merge.ts) | 将 Monaco 原文差异区间应用到原始正文 |
| [`src-tauri/src/lib.rs`](../src-tauri/src/lib.rs) | 原生命令、阻塞任务调度、取消标志、可信同步计划表及工作区持久化 |
| [`crates/diff-core`](../crates/diff-core) | 不依赖 Tauri、WebView 或前端框架的 Rust 比较与文件操作库 |

Rust 核心包含五个模块：

| 模块 | 职责及主要依赖 |
| --- | --- |
| `text` | 使用 `similar` 执行 Myers、Patience、Histogram；规则只变更比较键，结果坐标映射回原始行 |
| `structured` | 使用 `serde_json`、`serde_yaml_ng`、`yaml-rust2`、`roxmltree` 构建有类型的数据表示；精确 JSON 数值规范化使用 `num-bigint` |
| `files` | 编码与 BOM、换行信息、流式 BLAKE3、磁盘变更检查、原子保存；使用 `encoding_rs` 和 `tempfile` |
| `directories` | 目录递归、内容/元数据比较、隐藏项和忽略规则、链接与读取错误分类；使用 `ignore` |
| `sync` | 生成预览、保留原生快照、执行前重新核对、备份、原子复制、取消和部分结果 |

当前工作区持久化使用 JSON 文件，没有引入 SQLite。目录扫描也没有实现 Rayon 并行调度。后续需要这些能力时，应以实际测量和功能需求作为引入依据。

## 3. IPC 契约和任务生命周期

IPC 字段和枚举采用 camelCase，与 [`src/contracts.ts`](../src/contracts.ts) 对应。Rust 核心函数通过 `Result<T, String>` 返回可显示的错误；前端不能把异常当作空结果或“相同”。

| 命令 | 输入/输出要点 |
| --- | --- |
| `read_text_file` | 路径、可选读取编码 → 原文、编码、BOM、换行、字节数、磁盘指纹 |
| `inspect_save_target` | 保存目标路径 → 不存在返回 `null`，现有普通文件返回指纹，其他情况报错 |
| `save_text_file` | 正文、输出格式、目标路径、预期指纹 → 保存后的文件状态 |
| `compare_texts` | 两侧正文、文本规则 → 原始行区间与统计 |
| `compare_structures` | 两侧正文、格式和结构规则 → 有类型的变化及两侧规范表示 |
| `compare_folders` | 两个根目录、比较规则、任务 ID → 排序后的目录条目 |
| `preview_sync` | 根目录、规则、方向、任务 ID → 可显示的预览，并在原生进程中保留执行计划 |
| `execute_sync` | 计划 ID、任务 ID → 完成数、跳过数、问题列表、备份位置 |
| `discard_sync` / `cancel_job` | 分别丢弃尚未执行的预览、设置运行任务的取消标志 |
| `load_workspace` | 读取当前或上次工作区 JSON |
| `save_workspace` / `archive_workspace` | 原子更新当前快照、保留恢复归档 |

文件读取、保存、比较、扫描和同步通过 `tauri::async_runtime::spawn_blocking` 执行，避免在原生 UI 主线程中完成耗时工作。目录和同步任务在 `AppState.jobs` 中持有 `Arc<AtomicBool>`。哈希和复制循环会检查取消标志。

文本及结构比较目前通过请求版本号丢弃过期 UI 结果，并没有实现核心算法中途取消。不要把“结果已失效”解释成后台计算已经停止。前端对连续输入使用短延迟合并请求；原生算法仍可能完成已经启动的计算。

## 4. 可信同步计划

前端展示的 `SyncPlan` 只是预览数据。可执行的 `PreparedSyncPlan` 由 Rust 生成，内部另存根目录、原始条目快照、实际操作和计划 ID；这些字段不从前端回传的操作数组重建。

执行过程为：

1. `preview_sync` 强制使用内容比较，即使目录视图选择了快速元数据模式。
2. 核心生成计划，原生命令层把计划保存到内存表，只向前端返回公开预览。
3. 用户审阅后，前端调用 `execute_sync(planId, jobId)`。
4. 原生层从表中移走该计划。已消费、已丢弃或应用重启前生成的 ID 不能重用。
5. 核心取得写操作锁，重新扫描所有纳入范围的条目。新增、删除、内容变化或读取失败使计划失效，尚未进行任何修改。
6. 对每项操作再次检查路径、父目录和对应快照；覆盖与删除前生成备份。
7. 复制先写入目标文件系统中的临时文件，核对源内容并刷新文件数据，再原子发布。新文件使用不覆盖已有目标的方式发布。
8. 遇到取消或意外错误时停止后续操作，返回已完成和跳过数量。已完成操作不会自动撤回。

`copyRight` 表示左侧内容复制到右侧，`copyLeft` 表示右侧内容复制到左侧。`mirrorLeft` 以左侧为来源使右侧镜像，`mirrorRight` 相反。方向命名不得在 UI 和 Rust 之间重新解释。

此模型解决预览与执行分离，以及客户端操作列表被意外修改的问题；它不提供整个目录事务，也不是隔离恶意本地进程的文件系统沙箱。

## 5. 文本视图与规则结果分离

Monaco 原文差异视图用于逐行/逐字显示、导航和合并。Rust 比较规则用于计算“按当前规则是否相同”和统计。忽略大小写、空白或空行后，规则统计与原文高亮可能不同，因此界面明确区分两者。

原生 `TextHunk` 是以零开始、右端不包含的原始行区间。空行过滤只影响比较键；不得把过滤后数组的下标直接用于修改文件。结尾换行会产生一个末尾空行，坐标约定与编辑器保持一致。

UI 合并采用当前 Monaco 原文差异，应用前核对两侧模型版本，避免把旧差异写入新正文。合并属于编辑操作，进入撤销历史，只有用户保存时才写文件。选择原生 Patience 或 Histogram 不意味着 Monaco 的显示算法也被切换；未来若需要完全一致的自定义高亮，应增加单独的区间渲染层。

## 6. 会话和保存状态

打开的标签保存两侧正文、磁盘路径和指纹、输出编码/BOM/换行设置、比较规则、目录路径及各自已保存基线。正文或输出格式改变都会产生脏状态。命名会话保存这些状态的独立快照。

标签切换保留对应组件和 Monaco 模型，关闭标签才释放其编辑器资源；这保留当前运行期间的撤销和光标状态。撤销栈本身不写入工作区，重启后恢复的是正文和设置。

异步保存固定目标会话和请求快照。保存完成时更新磁盘基线，同时保留请求发出后产生的正文及格式修改。文件原始状态由磁盘指纹检查保护，不会因为工作区恢复或命名会话恢复而自动覆盖已被外部修改的文件。

工作区修改按队列写入，原生端另有工作区写锁。恢复失败暂停自动保存，恢复/重置前归档原快照。完整流程见 [工作区恢复](SAFETY_AND_FORMATS.md#8-工作区保存与恢复)。

## 7. 性能边界

目录内容哈希和文件复制使用固定大小缓冲区，不把每个被比较文件整体装入内存。目录条目与同步预览仍完整保留在内存中；列表虚拟化只减少 DOM 数量。

文本打开、编辑、规范表示和文本/结构对比目前都需要完整正文或解析树。Monaco 模型、两侧正文、已保存基线、规范表示及序列化工作区会增加内存占用。没有人为的文件大小或标签数量配额，但可处理规模仍取决于可用内存、磁盘及解析器能力。首版尚未实现内存映射、分页编辑、大文件专用只读模式、可暂停扫描或算法级取消。

同步为确认内容而重复读取源/目标，正确性优先于减少 IO。文件很多或文件很大时，预览和执行前校验都可能耗时，不能仅用目录列表刷新速度估算执行时间。

## 8. 迭代约束

后续开发应保留以下约定：

- 新比较模式可以复用契约、会话与任务层，但不得让展示数据直接成为可信文件操作参数。
- 增加忽略规则必须覆盖原始坐标映射和同步排除行为；错误不能转换成“文件不存在”。
- 新格式不能静默丢弃类型、重复键或数字精度后宣布相同。
- 新文件写入方式必须处理磁盘变化、已有目标、失败和取消；不得用先删除目标再重命名代替原子发布。
- 性能改造应说明内存和精确性取舍，不把解析失败、取消或近似结果标为精确相同。
- 未来能力与已交付基线分开记录。当前不包含三方合并、图片/二进制/Excel、Git/SFTP、压缩包、数据库、Word/PDF、CLI 或独立多窗口工作区。
