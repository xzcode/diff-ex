# Diff EX 产品需求 · 首版开发基线

## 目标

Diff EX 是面向开发、运维和日常文件管理的 EX 系列离线桌面工具。长期目标覆盖 Beyond Compare/WinMerge 的常用专业场景，首版优先解决文本、代码、目录和结构化配置文件比较。用户应能从打开两个输入开始，理解差异、修改/合并并明确保存，或审阅目录同步操作后执行。

平台目标 Windows、macOS、Linux；无需注册，无服务端，无自动上传。所有编辑器资源、语言和主题随包提供。

## 工作区与交互

- 首页提供三种实际可用入口：文本与代码、目录、结构化数据；示例必须是明确示例，不伪装成用户文件。
- 多标签独立保存状态。切换标签保留模型、光标和撤销栈，关闭标签时释放资源。
- 草稿与原始文件保存分开：工作区自动恢复不会偷偷写入原文件。
- 命名会话是一份可重复打开的快照，包含左右内容、路径、原始指纹、比较规则和草稿。
- 保留文件磁盘基线，恢复旧会话后仍通过指纹防止覆盖外部新版本。
- 工作区损坏/版本不兼容时停止自动覆盖；支持恢复前次快照或将原文件归档后重置。
- 英文/简体中文，默认跟随系统。深色/纯黑/灰色/柔和白色统一控件、边界与状态颜色。
- 纯界面标签不可选中；正文、路径、错误与差异值允许复制。

## 文本与代码

- 左右均可编辑，双栏和单栏显示，语法高亮、行内差异、同步滚动、差异导航、折叠相同行。
- 按差异块双向复制，整个文件复制，撤销与查找。
- 原生算法支持 Myers、Patience、Histogram。大小写、空白、空行、换行风格可作为比较规则。
- 原文显示、规则统计明确区分。使用原始差异坐标合并，不用经过删除空行/标准化的数据直接定位源文件。
- 原生支持 UTF-8、UTF-16LE/BE、GBK、GB18030。编码错误必须显式显示，不能有损替换字符。
- 保存前检查目标指纹，原子替换。编码/BOM/换行配置变化也算未保存编辑。
- 混合换行文件明确提示；编辑器规范化后保存必须让用户选择换行风格。

## 目录与同步

- 对左右根目录递归比较。内容模式流式哈希，元数据模式仅根据大小和修改时间判定。
- 显示相同、不同、仅左、仅右、类型冲突、读取失败。支持筛选、排序与虚拟化显示。
- 自定义排除与递归 .gitignore；镜像时采用两侧忽略策略并集，避免删除用户明确忽略的内容。
- 根目录相同或互相包含时拒绝同步。符号链接不跟随，特殊文件和类型冲突显式保留。
- 更新：源侧有文件则复制/覆盖，目标独有文件保留。镜像：以源侧为准，目标独有项目删除并备份。双向：只补齐单侧项目，同名不同保留为冲突。
- 预览包含实际操作方向、相对路径、原因与大小；执行只传原生保管的计划 ID。
- 执行前复查整体快照，每次写入再检查。覆盖/删除前保留备份。
- 取消或失败停止剩余操作，准确报告已经完成的项目和备份位置，不声称整个目录已回滚。

## 结构化内容

- JSON 对象键顺序无意义，数组默认有序，数字与字符串类型不同。
- 数字不得经浮点舍入后误判相同。JSON 精确十进制比较；YAML 无法无损表示时显式拒绝。
- 重复 JSON/YAML 键拒绝静默覆盖。YAML 自定义标签/复杂键等未支持语义明确报错。
- XML 属性顺序无意义，命名空间展开名称参与比较；子节点、混合文本、空白、注释和处理指令的顺序/内容保留。禁止 DTD 与外部实体读取。
- 搜索结构路径和值，区分新增、删除、值变化、类型变化。完整值详情可复制。
- 规范化视图统一展示只读 JSON，保存操作始终作用于原始文件。

## 资源与发布

- 不设置任意文件大小、标签数量、会话数或历史容量限制。
- 当前文本正文加载到内存，目录哈希流式执行，结果列表虚拟渲染。未来补充大文件分页及完整文本任务取消。
- 必须分别记录核心测试、前端构建、桌面编译、浏览器交互与平台安装验证；一个通过不代表其他项目通过。
- 安装包通过 GitHub Actions 产出。macOS Ad-hoc 签名，正式签名/公证和自动更新后续独立处理。
